# 安全说明

这个项目会拿到你的交易所 API 凭据。下面写清楚它做了什么、**没做什么**，
以及哪些威胁它挡不住——把边界说糊涂比不加防护更糟。

## 只读，不下单

`backend/app/account.py` 只实现 GET 查询，**没有任何下单、撤单、改杠杆的代码路径**。

这不只是承诺，是可以自己核对的：

```bash
grep -rn "POST\|DELETE\|PUT" backend/app/account.py    # 应当只有注释
```

配 API key 时请在交易所侧关闭交易与提现权限，只留读取。程序不需要更多权限，
关掉之后即使程序被攻破也动不了你的钱。

## 凭据加密

凭据以 **AES-256-GCM** 加密后存在 `credentials` 表里，主密钥在数据库之外
（默认 `backend/.master.key`，权限 600）。

每条密文都用 `(account_id, name)` 作为附加认证数据（AAD）绑定到它所属的槽位。
没有这层绑定的话，能改库的人可以把 1 号账户的 `api_secret` 整行复制到 2 号账户下
——密文照样解得开，于是 2 号账户拿着 1 号的密钥去请求。

### 这层加密防住什么

* 数据库文件**单独**泄露：迁移前的自动备份、误发出去的 `perpdesk.db`、
  云盘快照、手滑提交进 git。自托管工具最常见的泄露就是这一类。

### 防不住什么

* **能读服务器文件系统的人。** 主密钥默认就在同一台机器上，能拿到库的人
  多半也拿得到密钥。
* **能读进程内存的人。** 签名请求时凭据必然以明文存在于内存中。

想把边界推远一点，用环境变量注入主密钥，让它根本不落盘：

```bash
PERPDESK_MASTER_KEY=$(openssl rand -hex 32)   # 存进你的密钥管理器
```

代价是每次重启都要重新提供。

### 主密钥丢了怎么办

丢了就解不开了，没有后门。程序在"主密钥文件不存在、但库里还有密文"时会
**拒绝启动凭据功能并报错**，而不是声不响生成一把新的——那样只会把故障推迟到
下次取凭据时，而密钥何时消失、还能不能找回的现场早就没了。

确实找不回来的话，删掉 `credentials` 表里的记录重新录入即可；成交历史不受影响。

**备份时请把主密钥和数据库分开存**，放在一起等于没加密。

## 凭据不出后端

* 任何接口都不返回明文，对外只给掩码（`vault.status()`，形如 `TfEQ••••••••vjJh`）；
* 凭据不写日志；
* `backend/.env` 与 `*.key` 都在 `.gitignore` 里，部署脚本的 rsync 也排除它们
  （`--exclude '*.key'`——漏了这条的话 `--delete` 会把主密钥同步没）。

## 站点登录

应用层登录，单用户口令 + 服务端会话。

* 口令用 **scrypt**（标准库自带，内存硬，抗 GPU 爆破），n=2^15 约 32MB / 100ms。
  参数随哈希一起存库，以后调强度时老口令仍能验证，下次登录自动按新参数重算。
* 会话表只存 token 的 **sha256**，不存 token 本身——库泄露不等于会话被接管。
* Cookie 带 `HttpOnly`（XSS 偷不走）+ `SameSite=Lax`（挡跨站写操作）；
  `Secure` 按 `X-Forwarded-Proto` 自动判断，**HTTP 下不能置位**，否则浏览器
  根本不回传 cookie，表现成"登录了又弹回来"。
* 连续失败 10 次后全站禁登 15 分钟。单用户工具没有按用户隔离的意义，
  代价是攻击者能把主人也一起挡在外面几分钟——那远好过被爆破。
* 改口令会让**所有**会话失效（改口令的常见动机就是怀疑被人登进来了）。

**首次启动会自动生成口令并打进日志**，而不是"没设口令就不鉴权"——后者会让
一个刚部署、还没来得及设密码的实例在公网上裸奔。也可以用 `PERPDESK_PASSWORD`
自行指定。

日志位置取决于怎么跑的（注意**不在 journal 里**，`deploy/perpdesk.service`
把 stdout 重定向到了文件）：

```bash
grep "已生成站点登录口令" /var/log/perpdesk/api.log   # systemd 部署
./scripts/perpdesk.sh logs                            # 本地运行
```

WebSocket 单独做鉴权：HTTP 中间件管不到 WS 握手，只靠中间件的话那条流
就是整站唯一一个不需要登录的数据出口。

## 网络暴露

后端默认只监听 `127.0.0.1`，对外走 nginx 反代。`PERPDESK_HOST` **不要**设成
`0.0.0.0` —— 那会绕过 nginx 直接暴露后端，既没有 TLS，也拿不到 `X-Forwarded-Proto`，
cookie 的 `Secure` 判定会跟着失效。

### HTTPS

装好证书之后：

* 会话 cookie 自动带上 `Secure`（依据 nginx 转发的 `X-Forwarded-Proto`）；
* 网页里才能录入 API 凭据 —— 明文 HTTP 下后端直接返回 **421 拒收**。

这条是**拒绝**而不是提示后放行：密钥明文过网线跟贴在公告板上差不多，
而提示没人看、泄露不可逆。本机访问（`127.0.0.1`）放行，因为没有中间链路
可窃听，且首次配置往往就发生在还没证书的时候。自己在前面挡了 TLS、后端拿不到
`X-Forwarded-Proto` 的，用 `PERPDESK_ALLOW_INSECURE_CREDS=1` 开口子。

签证书见 `deploy/nginx.conf` 末尾的说明。要点：

* **域名必须是可注册域**。`sslip.io` / `nip.io` 这类把 IP 变域名的服务**不在**
  公共后缀列表里，所有子域名共用同一个 Let's Encrypt 限额（每周 50 张），
  实际上签不出来。`duckdns.org` 在列表里，可以用；自己买一个更省事。
* certbot 生成的 80 端口块默认 `return 404`，要改成重定向，否则用 IP 或别的
  Host 访问会直接 404。

## 没有多用户

这是单人自托管工具，**没有用户体系**，一个部署对应一个主人。

这是刻意的：多租户意味着要处理越权、会话劫持、用户枚举、密码重置链路，
每一样都是凭据泄露的新入口。对这类工具来说多租户不是加分项，是减分项。
